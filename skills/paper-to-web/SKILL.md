# 论文 → 中文交互导读网页

把论文改写成可以循序学习的网页：初学者先看懂问题与运行全貌，技术读者继续追踪变量、公式、数据和训练细节。默认中文，首次出现的术语附英文。交付真实可打开的网页文件，不停留在提纲或聊天摘要。

风格来自用户提供的 [RoboTTT 制作记录](https://chatgpt.com/s/cx_6ad8b99752748191ab5ad70953721740)，已将最终偏好保存在本 skill，日常使用不必重新访问链接。参考是设计证据，不是新论文的事实来源。

## 随 skill 提供的材料

- 写内容前读 [references/editorial.md](references/editorial.md)：解释深度、证据与训练细节。
- 布局前读 [references/visual-system.md](references/visual-system.md)：视觉参数和交互规则。
- 以 [assets/guide-template.html](assets/guide-template.html) 为可编辑底稿，内联样式与脚本，无构建依赖。里面是明确标注的版式样张，必须替换为新论文内容；样张的章节数量和演示不是每篇论文的强制结构。
- 需要核对参考来源或视觉时读 [references/reference-audit.md](references/reference-audit.md)，并查看其中截图。最终宽正文＋悬浮目录优先于早期固定侧栏。
- 用 [scripts/check_guide.py](scripts/check_guide.py) 检查结构和本地资源。它不验证论文事实或浏览器效果。

## 1. 建立论文证据，而后组织网页

用户只给 PDF 时，直接开始。默认面向有基础编程知识、对该子领域不熟的中文读者；沿用用户给定的主题、目录、用途和保存位置。

1. 读完整正文和相关附录，确认标题、作者、版本、年份；PDF 解析用可用的 PDF skill 或本地解析器。扫描件先 OCR，无法辨认的公式/数值明确保留缺口。
2. 对关键结构图、公式和结果表渲染对应 PDF 页并亲眼检查，不能仅凭抽取文字重画连线。
3. 在 `SOURCES.md` 记录关键主张 → PDF 页/章节/图表/公式 → 在网页中的位置。PDF 页码与印刷页码不同要说明。记录原文事实、解释性推断、教学示意、未报告项。
4. 检索作者官方项目页、同版本论文 HTML 和官方代码以寻找原图/动画/视频。检查身份和版本；源码当前默认配置不能直接冒充论文实验配置。外部来源不可访问时继续做 PDF 导读，说明媒体缺失，不编造资源。
5. 抽出一句主线：它解决谁的什么困难，关键机制改变了哪一步，哪些证据支持、哪些条件限制它。后续所有模块服务这条主线。

不要把 RoboTTT 的模块、训练方式、颜色名称或实验数值当作其他论文的预设。非模型论文按其真实对象改成实验流程、证明结构或研究设计；不硬塞“训练资源”。

## 2. 按学习顺序重新讲，而非照抄论文章节

默认阅读路径如下，可按论文内容合并、删减；篇幅随信息量变化。

| 层次 | 要回答的问题 | 合适的呈现 |
| --- | --- | --- |
| 首屏 | 这篇在做什么，为什么值得读？ | 论文身份、中文一句话、研究主张；少量有口径的关键结果 |
| 全貌 | 输入如何变成输出？ | 页面上部的整体 pipeline；输入、模块、输出、分支、循环与阶段标签 |
| 问题 | 旧方法在哪个具体场景失效？ | 一个贯穿全文的例子＋前后对照 |
| 机制 | 每一步实际处理什么？ | 模块展开、变量来源→变换→去向、关键公式＋白话和符号表 |
| 数据与训练 | 用什么数据、怎样组织、谁被监督、更新什么？ | 训练流程、数据/算力表，适用时提供可点选的序列演示 |
| 证据 | 结果有多强，在哪些条件下？ | 原始图表/严谨重绘、baseline、消融、失败与样本量 |
| 边界与回读 | 没证明什么，去哪里核对？ | 已知限制、未报告项、原文阅读路线和近处来源链接 |

每节先用几句话给结论，再用图和细节解释。给陌生符号先解释“是什么、从哪来、送到哪”，再讨论形状和推导。核心机制不能只藏在悬停气泡里。

## 3. 把图做成可以沿箭头读的解释

- 总览图从上到下或从左到右形成明确路径。模块名称使用“编码画面”“更新记忆”这类动作词；编号只用于定位，实际依赖由箭头表达。
- 图上直接标明画的是训练还是推理、单步还是完整轨迹、模型内部计算还是环境交互。适用时把内部迭代和跨时间循环画成不同路径，并标注返回什么、是否已执行。
- 边表示明确关系；数据传递、参数更新、梯度、控制流需要图例或文字区分。不要为了整齐添加虚假的串行顺序或架构节点。
- 变量卡片默认一行一个：左侧紧凑展示“来源 → 编码 → 变量”，右侧较宽解释含义、形状和下一站。区分 token 数、维度、时间步、原始状态、隐藏状态、模型参数和输出动作。
- 图形高度随内容；短框收紧，长框留足文字空间。复杂图在窄屏切换纵向或只在图内部滚动，不把整页缩成小字。需要时提供图的单独放大入口。
- 优先 HTML/CSS 或 SVG；交互应回答一个真实问题，例如切换实验条件、逐步展示训练样本与监督位置、点击符号查看含义。教学动画明确标“机制示意”，不能伪装成真实训练轨迹或内部可视化。

## 4. 实现与媒体

默认归档到本机 `~/Documents/paper-library/`（macOS Finder 的“文稿 → paper-library”），用户另指定位置时优先使用指定位置。每篇论文一个独立文件夹，建议命名为 `<论文年份>-<英文简称>`，例如 `2024-pi0/`；年份以论文为准，未知时省略。目录已存在时先核对是否同一篇论文，保留用户笔记与已有成品，不静默覆盖同名项目。不要把最终成品只留在下载、临时或预览目录，不修改无关业务代码。

每篇目录包含 `index.html`、`assets/` 和 `SOURCES.md`：将用户提供的 PDF 复制到 `assets/paper.pdf`，保留原文件；图片、视频和页面依赖使用相对路径。确保双击 `index.html` 就能阅读主体内容，不能依赖 agent、本地服务或构建命令。不同系统使用实际的文稿目录；云端 agent 无法写入用户本机时交付完整 ZIP 并说明应解压到哪里，不能声称已在本机归档。

维护文献根目录的静态 `index.html` 作为总目录首页。第一次创建，后续只增加或更新对应论文条目，保留其他条目和用户修改。每条列出标题、论文年份、一句话概述，使用相对链接通往导读、原文 PDF 和来源记录；论文页提供返回总目录的链接。普通 HTML/CSS 即可，无需数据库、后台服务或额外应用。完整论文文件夹可独立复制，总目录缺失不应影响正文阅读。

复制底稿后改成论文专属页面；沿用内联 CSS/JS 的简单静态实现。保持宽正文、左下可收起目录球、章节高亮/阅读进度、右下日夜切换。长段正文可限制行宽，图表与变量卡片充分使用页面宽度。

优先保留论文原图和官方动画原貌，在下方增加中文“看什么、说明什么、不能说明什么”。没有官方动画时才自制机制图，清楚标注。可用媒体保存为相对路径，视频配海报、播放控制、`playsinline`、`preload="none"` 或 `metadata`，不让页面一次加载所有大视频。大型/完整视频合集仅在任务需要时下载；只链接的资源明确需要网络。保留作者与出处，无法取得的资源提供可靠入口。

外部交互组件与正文隔离；本地 HTML 动画可用适当 sandbox 的 iframe，不给不需要的权限。数学式使用可读 HTML/SVG，复杂式子可使用环境已有的数学渲染方案；离线交付时保留本地依赖和可读退路。

本地成品与预览先完成。用户要求托管或发布时，使用当时可用的 Sites 等发布工作流；普通“做成网页”默认不擅自公开上传 PDF、资产或内容。

## 5. 验证后交付

1. 逐项复核关键指标、单位、比较口径、公式符号、模型连接和训练/推理差异；“未报告”不能被常识补齐。
2. 执行 `python3 <skill目录>/scripts/check_guide.py <产物>/index.html`，修复断开的锚点、本地资源与未替换占位。
3. 用实际浏览器查看桌面宽屏和手机窄屏；点击目录展开/选章/关闭、主题切换、公式释义、逐步演示和媒体。检查箭头、中文换行、文字对比、固定控件遮挡和横向溢出。打印样式保留静态解释与来源。可借本地 HTTP 预览解决 file URL 限制，不能把结构检查说成渲染测试。
4. 对照阅读路线确认：只看前几屏能说出问题和整体方法；继续读能追踪关键变量和训练过程；能找到证据及边界。删掉只重复原句、不帮助理解的装饰与交互。
5. 检查总目录与论文页之间的链接、原文 PDF 和本地媒体，确认最终目录有完整文件而非临时预览链接。简短交付总目录入口、论文网页和实际保存目录，说明以后可在 Finder 中双击打开；说明实际验证范围以及媒体/网络等真实限制。没有运行浏览器或没有拿到原始训练数据时，直说相应限制。
